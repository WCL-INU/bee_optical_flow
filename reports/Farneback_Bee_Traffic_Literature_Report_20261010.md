# 파른벡 옵티컬 플로우 기반 꿀벌 이출입 계수 시스템 선행연구 비교 보고서

작성일 2026년 10월 10일

## 1 목적과 비교 범위

본 보고서는 벌통 입구 영상에서 Farnebäck 옵티컬 플로우로 이출입 흐름을 정량화하는 시스템과 관련 선행연구를 비교한다. 비교 대상은 배경 차분 기반 꿀벌 계수, 입자 영상 유속계 기반 교통량 추정, YOLO 기반 검출 및 다중 객체 추적, 임베디드 장치의 영상 처리속도 실험이다.

**계수 정확도, 활동량 변화의 재현 정도, 연산 처리속도는 서로 다른 평가 항목이다.** 따라서 연구마다 발표한 지표와 측정 조건을 유지하여 제시하며, 서로 다른 지표를 하나의 정확도 점수로 바꾸거나 서로 다른 실험의 FPS로 알고리즘 우위를 판정하지 않는다. 본 시스템의 실측 결과는 제공되지 않았으므로 선행연구 수치와 나란히 배치할 수 있는 성능 값은 아직 없다.

기존 논의에서 다룬 활동량 지표와 현재 프로젝트 문서의 방향별 경계 흐름 누적을 함께 정리한다. 문헌의 발표 결과와 향후 검증을 위한 평가 설계는 별도 절에 제시한다. 문헌 조사 범위는 기존 대화에서 언급한 연구를 중심으로 하며, 전체 선행연구를 망라한 체계적 문헌고찰은 아니다.

## 2 비교 대상 시스템과 출력의 의미

### 2.1 현재 프로젝트 문서에 기록된 구성

프로젝트 참고 문서에는 다음 구성이 기록되어 있다. [P1–P3]

| 항목 | 기록된 내용 |
|---|---|
| 영상 처리 영역 | 벌통 입구와 주변 통과 공간을 포함하는 ROI |
| 움직임 계산 | 연속 ROI 영상 사이의 Farnebäck 밀집 옵티컬 플로우 |
| 방향 판정 | 입구 사각형의 네 경계에서 흐름을 안쪽 법선 방향으로 투영 |
| 방향 정의 | 입구 안쪽 법선 성분이 양수이면 IN, 음수이면 OUT |
| 현재 노이즈 처리 | 선택적 Gaussian blur와 픽셀 후보의 시간적 지속성 필터 |
| 지속성 필터 기본값 | decay 0.65, threshold 1.3 |
| 면적 필터 | 연결 성분 면적 필터는 선택 사항이며 기본 비활성 |
| 집계 | 3초 구간별 방향 흐름 및 계수 추정값 |
| 현재 사용하지 않는 구성 | 객체 ID 추적, YOLO, 히스테리시스 이벤트 검출, cooldown |
| 과거 구성과의 차이 | 흐름 버스트를 이벤트로 묶던 방식은 노이즈 안정화 단계에서 되돌림 |

참고 문서에 제시된 ROI 좌표 예시는 (1300, 1000)–(1640, 1232)로 폭 340 px, 높이 232 px이다. 이는 문서 좌표를 뺀 계산값이며 처리속도 실측값이 아니다. 입구의 하단 경계가 ROI 하단에 닿는 예시에서도 네 경계를 모두 포함한다. 실제 영상에서 관측 가능한 경계와 생물학적 입출 방향은 영상으로 확인해야 한다. [P1, P3]

이 구성에서 직접 계산되는 것은 픽셀 움직임과 경계 방향 흐름이다. 흐름을 마릿수로 환산한 값은 별도의 환산·보정과 검증이 필요한 계수 추정값이다. 흐름 합 자체에 ‘마리’라는 단위를 부여하지 않는다.

### 2.2 활동량과 마릿수의 구분

기존 대화에서 제안된 지표의 역할은 다음과 같이 구분할 수 있다. 아래 정의는 비교를 위한 정리이며 검증된 성능을 뜻하지 않는다.

| 출력 | 측정 대상 | 선행연구와 비교할 때의 기준 |
|---|---|---|
| motion_energy | ROI 내부 흐름 크기의 집계로 나타낸 움직임 수준 | 시간별 활동 변화 또는 수동 관측과의 관계 |
| in_score와 out_score | 입구 경계의 방향별 흐름 수준 | 동일 구간의 수동 IN·OUT 계수와 각각 비교 |
| net_flow | OUT 점수에서 IN 점수를 뺀 값 등 명시된 부호 정의 | IN·OUT 개별 결과와 함께 제시 |
| motion_area | 배경 차분 등으로 얻은 움직임 영역의 크기 | 움직임 면적의 보조 지표 |
| 계수 추정값 | 방향 흐름을 마릿수로 환산한 값 | 환산 규칙을 고정한 뒤 별도 시험 영상에서 오차 평가 |

motion_energy라는 이름만으로 에너지의 물리 단위가 정해지지는 않는다. 흐름 크기 합인지 제곱합인지, ROI 면적으로 나눈 값인지 계산식을 반드시 명시해야 한다. OpenCV Farnebäck의 출력은 영상 좌표의 변위 벡터이므로 프레임 간격과 영상 축척도 함께 기록해야 한다. [8, 9]

초기 논의의 1분 집계와 현재 문서의 3초 집계는 평가 목적이 다르다. 3초 결과는 단시간 변화와 잔류 노이즈를 확인하는 데 사용하고, 1분 결과는 같은 원자료를 추가 집계한 활동량 비교로 구분한다. 서로 다른 구간 길이의 결과를 직접 비교하지 않는다.

## 3 꿀벌 계수와 활동량 선행연구

### 3.1 발표 결과 비교

| 연구 | 방식과 평가 대상 | 실제 발표된 수치 | 수치가 나타내는 것 | 본 시스템과 비교할 때의 범위 |
|---|---|---|---|---|
| Tu 등 2016 [1] | 배경 차분을 사용하는 영상 기반 꿀벌 수 및 입출 활동 분석 | 꿀벌 수 R² 0.987, 입구 방향 활동 R² 0.953, 출구 방향 활동 R² 0.888 | 수동 관측과 시스템 결과의 회귀 관계 | 활동량 또는 구간별 계수 결과의 관계를 비교하는 참고 자료 |
| Ngo 등 2019 [2] | 실시간 영상 기반 다중 꿀벌 추적 및 입출 계수 | 수동 계수 대비 자동 계수 정확도 93.9 ± 1.1% | 저자가 정의한 자동 계수 정확도 | 정의와 시험 조건을 유지하여 인용하며 F1이나 R²로 변환하지 않음 |
| Kulyukin 등 2021 BeePIV [3] | 움직임 영상을 입자 영상으로 변환하고 PIV로 교통 흐름 추정 | 수동 전방향 움직임 평가에 30초 영상 12개, 총 8,928 프레임 사용 | 프레임의 움직임과 방향 교통량을 분석한 연구 구성 | 움직임 기반 활동량 추정 선행연구로 비교; Farnebäck 구현으로 분류하지 않음 |
| Lei 등 2024 [4] | YOLOv8m + OC-SORT + 입구 box 계수 | IN F1 91.49%, OUT F1 89.08%, 21.99 FPS | 방향별 입출 계수와 해당 실험의 처리속도 | 방향별 계수 검증의 참고; 픽셀 흐름 점수와 F1을 바로 비교하지 않음 |
| Kulyukin과 Kulyukin 2023 [5] | YOLOv3, YOLOv4-tiny, YOLOv7-tiny의 비행 꿀벌 객체 검출 및 자원 평가 | 5,819장에 꿀벌 객체 23,173개 라벨링; 별도 120개 영상의 3,600장 평가 | 프레임 단위 객체 검출과 운용 자원 평가 | 객체 검출 및 자원 비교 자료; 입출 이벤트 F1 자료로 취급하지 않음 |

Tu 연구의 R²를 98.7% 계수 정확도라고 표현하면 지표의 의미가 바뀐다. Ngo 연구의 ±1.1%도 분산 종류와 계산식을 추가 확인하지 않은 상태에서 신뢰구간이나 표준편차로 단정하지 않는다. 서로 다른 영상·촬영 조건에서 얻은 값이므로 위 표는 발표 결과의 병렬 정리이다. [1, 2]

BeePIV는 PIV 기반 방법이며 Farnebäck 밀집 옵티컬 플로우와 다른 알고리즘이다. 이 연구는 방향별 교통 곡선과 프레임의 전방향 움직임을 다룬다. 논문에서는 방향별 움직임을 충분히 수동 라벨링한 추가 검증이 필요하다고 설명한다. 따라서 전방향 움직임 평가와 방향별 마릿수 계수를 동일하게 취급하지 않는다. [3]

### 3.2 동일 논문 안에서 수행한 비교

Lei 등은 검출기 YOLOv8m을 기반으로 추적 알고리즘과 계수 경계 구성을 비교했다. 다음은 원문 Table 5와 Table 6의 수치이다. 두 표의 계수 방식과 시험 결과를 함께 표시한다. [4]

| 계수 방식 | 추적 알고리즘 | IN F1 % | OUT F1 % | FPS |
|---|---|---:|---:|---:|
| 단일 선 | ByteTRACK | 68.13 | 75.21 | 22.48 |
| 단일 선 | OC-SORT | 73.78 | 74.40 | 21.67 |
| 단일 선 | Deep OC-SORT | 58.48 | 63.27 | 17.23 |
| Box | ByteTRACK | 85.98 | 85.89 | 24.51 |
| Box | OC-SORT | 91.49 | 89.08 | 21.99 |
| Box | Deep OC-SORT | 83.55 | 79.77 | 17.49 |

OC-SORT + box의 IN precision과 recall은 각각 94.29%, 88.85%이고, OUT precision과 recall은 92.73%, 85.71%이다. 이 값은 해당 논문 Table 6의 결과이며, 본 시스템의 예상 정확도에 대입할 수 없다. [4]

이 비교는 경계 구성과 계수 규칙까지 평가 대상임을 보여주는 실험 자료다. 본 시스템도 네 경계의 흐름을 사용하는 만큼, 계수 경계와 입력 ROI를 검출·움직임 계산 알고리즘과 함께 명시해야 한다.

동일 논문의 검출선 위치 실험 Table 7과 Table 8에는 다른 F1 값이 제시된다. 해당 값은 위치 실험의 결과이므로 위 표의 전체 계수 방식 평가와 섞어 ‘논문의 최고 정확도’ 하나로 정리하지 않는다. [4]

## 4 처리속도와 자원 사용 선행연구

### 4.1 Raspberry Pi 4의 Farnebäck 측정 자료

Choi 등은 일반 움직임 객체 검출·추적 실험에서 Raspberry Pi 4를 사용했다. Farnebäck 비교 조건의 처리 영상 크기는 384 × 288 px이며, video 4는 해당 크기로 축소한 video 4S이다. 아래 값은 원문 Table 1에 제시된 Farnebäck 방법의 결과다. 이 논문의 제안 방법은 sparse optical flow 기반이며 아래 Farnebäck 행은 비교 방법이다. [6]

| 영상 | 영상 크기 | Precision | Recall | F-score | FPS 원문 표기 | 1000/FPS 계산값 ms |
|---|---|---:|---:|---:|---:|---:|
| video 1 | 384 × 288 | 0.80 | 0.70 | 0.75 | 4.27 ± 0.06 | 234.19 |
| video 2 | 384 × 288 | 0.80 | 0.78 | 0.79 | 4.29 ± 0.05 | 233.10 |
| video 3 | 384 × 288 | 0.83 | 0.66 | 0.74 | 4.23 ± 0.05 | 236.41 |
| video 4S | 384 × 288 | 0.89 | 0.74 | 0.81 | 4.23 ± 0.06 | 236.41 |

마지막 열은 발표된 평균 FPS의 역수로 계산한 처리율 환산값이다. 개별 프레임 실행시간의 평균·중앙값·p95를 직접 측정한 값이 아니다. 원문의 ± 표기는 유지했으며 본 보고서에서는 분산 종류를 추가 해석하지 않는다.

이 값은 꿀벌 입출 계수 실험 결과가 아니며, 현재 프로젝트의 340 × 232 ROI 또는 지속성 필터를 적용한 결과도 아니다. ROI 면적비만으로 처리시간을 환산하지 않는다. [6]

### 4.2 Raspberry Pi 4의 YOLO 측정 자료

Shalash 등은 YOLOv8부터 YOLOv12까지 여러 단일 보드 컴퓨터에서 평가했다. Raspberry Pi 4의 YOLOv8n 수치는 다음과 같다. 수치 위치는 저자 사전공개본 v1 Table 6이며, 같은 수치는 출판본 검색 결과에서도 확인된다. [7a, 7b]

| 모델과 장치 | 전력 모드 | FPS | 1000/FPS 계산값 ms |
|---|---|---:|---:|
| YOLOv8n, Raspberry Pi 4 | Standard | 0.95 | 1052.63 |
| YOLOv8n, Raspberry Pi 4 | Low | 0.34 | 2941.18 |
| YOLOv8n, Raspberry Pi 4 | High | 0.97 | 1030.93 |

이 연구는 COCO를 사용하는 일반 객체 검출 평가다. 꿀벌 입출 시스템의 성능이 아니며 NCNN, ONNX, TensorRT 등 다른 실행 환경의 Raspberry Pi 성능을 대표하는 수치도 아니다. 이 표의 수치만으로 현재 프로젝트의 실행시간을 예측하지 않는다. [7a, 7b]

Choi와 Shalash는 모두 Raspberry Pi 4 자료를 포함하지만 영상, 처리 단계, 입력 설정 및 실행 환경이 같은 실험은 아니다. 두 논문의 FPS를 나누어 Farnebäck이 YOLO보다 몇 배 빠르다고 결론 내릴 수 없다. 하드웨어 명칭 일치만으로 직접 비교 조건이 충족되지는 않는다.

Kulyukin 2023 수치는 원문 Table 7이다. kWh/h는 평균 전력에 해당하며 세 값은 각각 210 W, 200 W, 180 W로 단위 변환할 수 있다. GPU 컴퓨터에서의 전력 자료를 Raspberry Pi 전력이나 알고리즘 단독 소비전력으로 대입하지 않는다. [5]

해당 논문 Table 4의 Precision·Recall 열은 일반적인 TP/(TP+FP), TP/(TP+FN) 정의와 일치하지 않는 표기가 있다. 예를 들어 TP 377, FN 581, FP 0인 행에 Precision 0.39, Recall 1.00이 표시된다. 본 보고서는 그 열을 표준 정의의 정확도 비교에 사용하지 않고, 위 자원 자료와 평가 구성만 인용한다. [5]

## 5 처리시간에 관한 비교 원칙

### 5.1 핵심 연산과 전체 시스템을 구분

OpenCV의 Farnebäck는 영상의 모든 위치에 대해 흐름을 계산한다. 고정 ROI와 고정 파라미터에서는 객체마다 별도의 흐름 계산을 반복하는 구조가 아니다. 따라서 벌 수가 증가하면 Farnebäck 핵심 연산 시간이 벌 수에 비례하여 증가한다고 단정할 근거는 없다. [8, 9]

다만 ‘벌 수와 완전히 무관하게 항상 같은 시간이 걸린다’는 표현도 실측 근거 없이 사용하지 않는다. 흐름 마스크의 연결 성분 처리, 선택적 필터, 영상 입출력, CPU 상태 등은 전체 프레임 처리시간에 영향을 줄 수 있다. 이는 구현 구조에서 도출한 비교상 구분이며 현재 프로젝트에서 측정된 결과가 아니다.

YOLO도 고정 입력 크기의 신경망 순전파와 검출 후처리·추적을 분리해야 한다. 검출 박스 수가 달라져도 전체 시스템 시간이 일정하다고 전제하지 않는다. 본 비교에서 ‘추론 시간’이라는 표현은 YOLO 신경망에 사용하고, Farnebäck는 ‘흐름 계산 시간’으로 표시한다.

### 5.2 시간을 측정하는 범위

| 시간 지표 | Farnebäck 시스템 | YOLO 기반 시스템 |
|---|---|---|
| 입력 처리 | 디코딩, ROI 추출, 회색조 변환, blur | 디코딩, ROI 추출, resize와 입력 변환 |
| 핵심 알고리즘 | Farnebäck 흐름 계산 | 신경망 순전파 |
| 후처리 | 경계 투영, 후보 마스크, 지속성 및 면적 필터, 흐름 집계 | NMS 등 검출 후처리, 추적, 입출 판정 |
| 결과 출력 | CSV 기록, 미리보기 생성 등 | 같은 출력 범위 적용 |
| 전체 프레임 시간 | 위 단계의 일관된 총합 | 위 단계의 일관된 총합 |

순전파 시간과 영상 읽기·추적까지 포함한 시간을 같은 열에 섞지 않는다. 카메라 취득 FPS, 분석 입력 FPS, 실제 처리 FPS도 별도로 기록한다. 비동기나 병렬 처리가 있으면 FPS의 역수가 개별 프레임 지연시간과 같다고 전제하지 않는다.

## 6 본 시스템에 적용할 비교 분석 기준

아래 항목은 향후 실험의 평가 설계다. 발표된 선행연구 수치 또는 본 시스템의 측정 결과가 아니다.

### 6.1 출력 유형별 정확도 평가

| 평가 목적 | 지표와 기록 | 해석 범위 |
|---|---|---|
| 활동 변화 재현 | 동일 구간의 방향별 흐름 점수와 수동 계수에 대한 상관, 명시된 회귀 R² | 관계가 강한지 평가; 마릿수 일치 여부와 구분 |
| 계수 추정 정확도 | IN·OUT별 MAE, RMSE, bias, 총계 오차 | 고정된 환산 규칙의 오차 |
| 방향별 계수 검출 | IN·OUT precision, recall, F1 | 개별 이벤트 또는 개체와의 매칭이 가능한 출력에서만 사용 |
| 조용한 구간의 출력 | 잔류 방향 흐름, 구간별 분포, 거짓 활동 응답 | 노이즈 반응 평가 |
| 시간대별 변화 | 3초 원자료와 1분 재집계 결과 | 단시간 오차와 장시간 추세를 구분 |

현재의 3초 누적 방식은 개별 이벤트를 출력하지 않는다. 구간의 추정 마릿수만으로 TP·FP·FN을 정하거나 이벤트 F1을 계산하지 않는다. 개별 사건의 시간·방향과 매칭 규칙이 없는 경우에는 구간별 오차와 활동량 관계를 평가한다.

구간 k의 수동 계수를 N_k, 환산 추정값을 Nhat_k라고 정의하면 MAE는 mean(abs(Nhat_k - N_k)), RMSE는 sqrt(mean((Nhat_k - N_k)^2)), bias는 mean(Nhat_k - N_k)로 기록한다. IN과 OUT은 각각 계산한다. 순출입 차이만 평가하면 입출 오차가 상쇄될 수 있으므로 방향별 결과를 보존한다.

R²는 계수 추정값 자체의 오차 지표로 계산했는지, 점수에서 계수로 회귀한 결과의 적합도로 계산했는지 구분한다. 상관계수의 제곱을 아무 설명 없이 계수 정확도라고 쓰지 않는다.

### 6.2 동일 조건 비교에 필요한 기록

| 구분 | 고정하거나 명시할 조건 |
|---|---|
| 영상 | 동일 원본, 시험 구간, 실제 프레임 시각, 누락 프레임 정책 |
| 공간 | 카메라 위치, ROI 좌표, ROI 크기, 입구 경계, resize 비율 |
| 시간 | 분석 프레임 간격, 프레임 스킵, 3초 구간 시작 시각, 1분 집계 규칙 |
| Farnebäck | pyr_scale, levels, winsize, iterations, poly_n, poly_sigma, flags |
| 흐름 후처리 | magnitude와 normal-flow 임계값, blur, 지속성, 면적 필터, 환산식 |
| YOLO | 모델·가중치, 입력 텐서 크기, 수치 정밀도, backend, confidence, NMS, 추적 설정 |
| 장치 | 보드 모델, OS, CPU 설정, 스레드 수, 메모리, 냉각, 온도, 다른 작업 |
| 계측 | 워밍업 제외 범위, 반복 수, 평균, 중앙값, p95, 표준편차, 처리 FPS |
| 평가 분할 | 보정·파라미터 선택 영상과 최종 시험 영상의 분리 |

보정용 영상에서 환산계수를 정한 뒤 시험 영상에서는 고정한다. 조용한 영상 두 개의 출력이 낮아지는 것만으로 계수 정확도가 확보되었다고 판단하지 않는다. 실제 꿀벌 움직임이 많은 영상에서 신호가 보존되는지 별도로 확인한다. [P2, P3]

### 6.3 필요한 실험 비교

| 실험 | 비교할 구성 | 기록할 결과 |
|---|---|---|
| 노이즈 처리 영향 | Raw 흐름, blur 적용, 지속성 적용, 선택적 면적 필터 | 조용한 구간 잔류 흐름과 실제 활동 신호의 변화 |
| ROI 크기 영향 | 같은 장면의 여러 ROI·축척 | 핵심 연산 시간, 전체 시간, 정확도 또는 활동 관계 |
| 장면 활동 수준 영향 | 고정 설정의 저활동·중활동·고활동 구간 | 처리시간 분포와 신호 수준; 벌 수 효과와 노이즈 효과 구분 |
| 프레임 간격 영향 | 동일 원본에서 여러 분석 간격 | 변위·시간 정규화 조건, 계수 오차와 처리속도 |
| 방법 간 비교 | Farnebäck 누적, 배경 차분 기반 방법, YOLO 기반 계수 | 공통 출력에 대한 구간별 평가와 전체 처리시간 |

기존 논의의 10 FPS는 프레임당 100 ms 처리 예산에 해당한다. 이는 목표 조건이며 현재 달성한 결과가 아니다. 평균 시간뿐 아니라 p95, 누락률과 연속 운용 조건도 함께 기록하여 예산 충족 여부를 평가한다.

## 7 비교 결과의 정리

문헌에서는 배경 차분 기반 활동 분석의 R², 추적 기반 자동 계수 정확도, YOLO 기반 방향별 F1, 임베디드 처리속도와 GPU 자원 사용 자료가 각각 발표되어 있다. 이 결과는 같은 측정 대상을 같은 조건에서 평가한 단일 비교표가 아니다.

본 시스템과 가장 먼저 맞춰야 할 비교 단위는 **방향별 3초 흐름 점수 또는 계수 추정값**이다. 마릿수 환산을 고정한 경우에는 구간별 계수 오차를 평가하고, 흐름 점수를 그대로 사용하는 경우에는 활동 변화와 수동 계수의 관계를 평가한다. 개별 이벤트 검출 성능은 이벤트 대응이 가능한 출력이 마련된 경우 별도 평가한다.

본 보고서의 비교 근거만으로는 본 시스템의 계수 정확도, 저전력 우위, YOLO 대비 속도 우위를 결론 내릴 수 없다. 발표 수치를 인용할 때는 연구·평가 대상·지표·조건을 함께 제시하고, 본 시스템의 결과는 동일 영상과 동일 장치에서 측정한 뒤 구분하여 추가한다.
